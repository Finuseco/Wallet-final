# Wallet 2.3 / code 12 — scanner et confirmations financières

Le scanner lit QR/DataMatrix, EAN13/EAN8, UPC, Code128/39 et ITF. L’analyse tient compte des strides de luminance, des rotations et des images inversées. Le flash suit l’état CameraX et les ressources caméra/exécuteur sont libérées. Les images importées sont échantillonnées avant décodage. Les parcours de QR wallet/crypto et d’identification agent sont conservés ; un code produit ouvre le parcours commercial.

Le mobile demande le catalogue réel au backend. Un code présent dans plusieurs boutiques affiche les choix, puis une quantité. Le montant du QR n’est pas utilisé comme prix d’article. Un devis serveur présente le bénéficiaire, les articles, les promotions, la devise, la conversion, les frais et le total débité. Le PIN autorise ce devis ; une erreur réseau n’affiche pas de reçu. Le même jeton permet de reprendre un paiement incertain sans nouveau débit.

La demande de crédit présente les conditions renvoyées par le web : taux configuré par durée, garantie, échéances, dernière échéance arrondie, pénalités illustratives et prélèvements automatiques. Le titulaire doit accepter explicitement. Les remboursements manuels ou d’échéance passent aussi par une confirmation du montant, des frais, de la devise et du reste. Le reçu et la référence viennent du serveur. Les pénalités incluses et le déjà payé sont visibles ; les réponses tardives d’un ancien compte ne mettent pas à jour ces confirmations financières.

Prérequis : déployer la version backend correspondante et ses migrations après revue/sauvegarde. Les anciennes entrées de scan de paiement exigent maintenant un devis ; les anciens QR POS sans articles doivent être régénérés par la caisse web. Les contrats API de prêts simulés ont été retirés. Les clés de signature de production n’ont pas été utilisées ; l’APK release de validation est non signé et nécessite une signature officielle.

Validation : builds debug/release et lintVitalRelease ; programme JVM temporaire avec les classes/adaptateurs générés réels pour les contrats de données et le décodage QR/EAN/Code128/DataMatrix en images normales, tournées et inversées. Les fixtures et programmes de vérification sont hors dépôt et ne sont pas livrés dans l’APK. Aucune validation sur caméra physique, compte financier réel, réception SMTP ou passerelle USSD n’a été effectuée dans cet environnement. Les rapports de livraison distinguent ces limites.
